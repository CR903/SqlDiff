# E2E 环境配置三条坑

三条都来自 `10-05-e2e-env-readiness`（2026-10-05），通用、与具体框架无关。

## 一、加载 `.env` 类文件进环境变量：已存在的键一律不覆盖

**规则**：判据用 `hasOwnProperty`（键是否存在），**不是**真值判断。

```ts
// 错：外部注入空字符串时会被文件里的值顶掉
if (env[key]) continue;

// 对：空串也算「已设置」
if (Object.prototype.hasOwnProperty.call(env, key)) continue;
```

**为什么这是安全边界**：外部注入的可能是 CI 的 secret、或开发者命令行临时指定的 host。判据换成真值判断后，`PASSWORD=`（空串）会被文件里的旧密码覆盖——「显式清空」变成了「静默回退到陈旧凭据」。同理，文件里残留的旧 host 会在 IP 变更后被误用，而这种失效**看起来像跑通了**。

**自证方法**：改判据后跑套件应变红；再加一条「外部空串不被文件覆盖」的用例锁住。

## 二、目标机地址是动态的，代码里不给默认地址

**规则**：虚拟机 / 容器 / 弹性 IP 的地址只能从环境变量传，**不给代码默认值**。缺失时 skip 并**点名变量 + 在 skip 消息里写明为什么不给默认值**。

```
缺少 E2E_MYSQL_57_HOST。目标机是虚拟机，IP 每次重启都会变，因此代码里刻意不提供默认地址；
请在 .env.e2e 中填入真实 host 与密码（Playwright 会自动加载该文件），不要把 IP 写死回代码里。
```

**为什么不 scan 网段自动发现**：自动发现会把「用户指定的测试目标」变成「碰巧扫到的某台机器」，报告里说比了 A 库、实际可能连的是 C 库，破坏可追溯性。人工填 env 麻烦，但每次比的目标明确可复查。

**为什么 skip 消息要写「为什么」**：不写这句，下一个维护者只看到「缺个环境变量」，很自然会「顺手」把默认值加回去，于是回到静默连错机器的状态。**skip 消息是防回退的护栏，不是提示文案。**

## 三、lint 的 ignore 列表要与 `.gitignore` 同步

**规则**：任何会产生本地产物的 harness（e2e 报告、覆盖率、构建缓存），它的输出目录必须同时进 `.gitignore` 和 ESLint 的 `ignores`。

**症状**：跑过一次 e2e 之后 `npm run lint` 报上千条 `no-undef`，全部来自报告目录里的压缩第三方 bundle。

**为什么容易漏**：这类 harness 之前没人真跑（或跑完就清目录），门禁是绿的；一旦它变成「填个配置文件就能跑」的常规路径，第一次跑完就会把质量门禁打红——而且**报错内容与真正的问题完全无关**，容易被误判成代码坏了。

**预防**：新增任何会写本地产物的工具时，同步检查三处——`.gitignore`、ESLint `ignores`、CI 是否显式跳过。
