# 日志 → 知识沉淀判据

`AGENTS.md` 的 **P2 沉淀门禁**引用本文件。`trellis-check` 阶段必须按这里的三问逐条自检；命中却没沉淀，**拦截 archive**。

## 背景

任务日志（`docs/daily/*.md`）记的是"这次发生了什么"。知识库（`docs/knowledge/`）记的是"下次遇到同类问题直接照做"。

差别在于**时效**与**载体**：日志是一次性的、挂在任务上的；知识是长期有效的、跨任务复用的。把该沉淀的东西留在日志里，下次还得靠人肉翻历史——那就等于没写。

## P2 三问

对日志的「踩到的坑」和「可沉淀知识」两节逐条问。**三问全 yes 才需要沉淀**；任一 no 就不沉淀，在日志里写明理由。

### 问一：是「坑」还是「任务细节」？

坑 = 下次会再踩、且踩了会浪费时间或出错。
任务细节 = 只在这个任务成立、换个任务就不适用。

- ✅ 坑：某个测试用 `setTimeout` 释放 object URL，跨 `afterEach` 泄漏到下一个用例 → 谁写这类测试都会踩
- ❌ 任务细节：本次新增的 IPC 方法叫 `preflight:run` → 只有这个功能有

### 问二：是「通用解法」还是「本次特例」？

通用解法 = 能写成"遇到 X 就做 Y"的规则，且这个规则不依赖具体模块名。
本次特例 = 只能描述本次改了什么，无法归纳。

- ✅ 通用解法：断言要打契约，不能打依赖库内部格式（升级补丁版会让套件变红而行为没变）
- ❌ 本次特例：把 `XxxReport` 加到 `yyy.ts` 里 → 无规则可循

### 问三：值得开「新文件」还是并入现有分类？

- 只是同一分类下补一个知识点 → **并入现有文件**，不新建
- 出现了现有分类装不下的新主题 → 新建 `docs/knowledge/<端>/<分类>/<file>.md`

分类体系目前只落地了 `common/`，新分类出现前先确认它至少能装下 3 个知识点。

## PR Checklist

沉淀时逐项确认：

- [ ] 文件放在 `docs/knowledge/<端>/<分类>/<file>.md`，命名 kebab-case
- [ ] 内容是**规则**（「遇到 X 就做 Y」），不是本次改动的流水账
- [ ] 没有真实凭据：`fake-*` 占位，无主机名 / 密码 / 私钥
- [ ] 已更新 `docs/knowledge/<端>/<分类>/index.md`
- [ ] 已更新 `docs/knowledge/<端>/index.md`
- [ ] 已更新 `docs/knowledge/index.md`
- [ ] 在对应 `docs/daily/*.md` 的「可沉淀知识」勾选"已写入"并给出路径

**索引要动几级？** 新建或改动任一分类文件时，沿路径**分类 → 端 → 根**逐级向上更新，直到 `docs/knowledge/index.md`，一级都不能漏。分类文件的 `index.md` 列文件，端与根的 `index.md` 列分类——两者列的不是同一种东西。漏掉任何一级，该知识点对下一个人就等于不存在。

## 拦截条件

出现以下任一情况，`trellis-check` **拦截 archive**：

1. 日志「踩到的坑」非空且描述了可复现的失败现象，但 `docs/knowledge/` 下无对应沉淀
2. 沉淀文件写了，但任一级 `index.md` 未更新（沉淀等于不可检索）
3. 三问其实都 no（该 no 却硬沉淀，或该 yes 却只勾"无需沉淀"且未写理由）——属于判据被绕过

第 3 条的反向情形同样拦截：勾了"无需沉淀"但没写理由，等于把判据交给下一个人重猜。

## 清理与改写门禁

同一判据对**清理文档**也适用：删除或改写 spec / docs 里的引用后，回读被改位置的**前后各两行**，确认没有留下多余空行、孤立列表项、断裂表格或悬空交叉引用。

具体坑位与解法见 [`docs/daily/2026-10-05_docs-spec-drift-cleanup.md`](../../../daily/2026-10-05_docs-spec-drift-cleanup.md) 的「踩到的坑」。
